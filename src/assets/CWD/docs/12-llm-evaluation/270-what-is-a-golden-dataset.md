## What is a Golden Dataset?

A **golden dataset** is a carefully prepared set of **trusted test cases with expected/verified answers or behavior** that we use to evaluate and regression-test an AI system.

For CWD, it acts as our **standard benchmark**.

### CWD example

Suppose we have this test case:

```text
Input:
"Give me a customer briefing for C12345"
```

The golden dataset defines what CWD is expected to do:

```json
{
  "input": "Give me a customer briefing for C12345",
  "expected_intent": "customer_briefing",
  "expected_delegators": [
    "sales",
    "it"
  ],
  "expected_workers": [
    "customer_worker",
    "incident_worker"
  ],
  "expected_sources": [
    "Salesforce",
    "ServiceNow"
  ]
}
```

The actual CWD execution is then compared against this expected behavior.

```text
Golden Dataset
      ↓
    CWD
      ↓
Actual Result
      ↓
Compare with Expected Result
      ↓
Pass / Fail
```

### What should a CWD golden dataset contain?

I would include different categories:

```text
Golden Dataset
├── Normal cases
├── Edge cases
├── Failure cases
├── Ambiguous requests
├── No-data cases
├── Hallucination cases
├── Security/authorization cases
├── MCP/tool failure cases
└── Multi-agent cases
```

For example:

| Test case                 | Expected behavior      |
| ------------------------- | ---------------------- |
| Customer briefing         | Sales + IT Delegators  |
| Customer not found        | Controlled error       |
| No incidents              | Don't invent incidents |
| Unauthorized customer     | Deny access            |
| ServiceNow timeout        | Retry/recovery         |
| Insufficient RAG evidence | Abstain                |
| Ambiguous customer ID     | Ask clarification      |

### Where do golden datasets come from?

I can build them from:

* **Historical production queries** that were manually validated
* **Domain-expert-created scenarios**
* **Synthetic test cases**
* **Known production failures**
* **Security and edge cases**
* **Regression cases from previous releases**

The important part is that the expected result is **verified**, not simply generated by another LLM and assumed to be correct.

### Why is it important?

Suppose I change:

```text
GPT model
Prompt
RAG strategy
Chunking
Retriever
Coordinator routing
Worker logic
```

I run the same golden dataset again.

```text
Version 1 → 94% groundedness
Version 2 → 97% groundedness
```

I can objectively identify whether the change improved or degraded the system.

### Golden dataset vs production data

**Production data:**

> What users actually asked.

**Golden dataset:**

> A curated set of cases where we know what the correct behavior should be.

Production cases can eventually become golden cases **after validation**.

### Interview-ready answer

> **“A golden dataset is a curated and validated set of representative test cases with expected answers or expected system behavior. In CWD, it contains normal, edge, failure, security, RAG, and multi-agent scenarios. For example, a Customer Briefing test case specifies the expected intent, Sales and IT Delegators, required Workers, and authoritative sources. Whenever I change the model, prompt, retrieval strategy, or agent workflow, I run the golden dataset and compare metrics such as routing accuracy, retrieval quality, groundedness, factual accuracy, and task completion. This gives us a consistent regression benchmark.”**
